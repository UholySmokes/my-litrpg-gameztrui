# Godot 4 Vertical Slice (Online + Singleplayer Local)

This folder contains a desktop-first Godot 4 scaffold for the locked vertical slice:

1. One tiny 2D map loop (`map_village_square` <-> `map_training_glade`).
2. One NPC (`npc_guide`) with a quest-flag chain.
3. One encounter gate transition trigger.
4. Save + load via local singleplayer state or online sync, depending on runtime mode.
5. Story beat/prose panel rendering from canonical state.
6. System-first character creation backed by shared game-core canon.

## Godot Version

Use Godot `4.6.1 stable` plus the matching Android export templates and a JDK `17` install for Android export.

## Android Export Profiles (Dual Track)

`godot/export_presets.cfg` now defines staged Android presets:

1. `Android Developer Singleplayer` -> local-only debug APK (`build/android/developer-singleplayer.apk`).
2. `Android Internal Debug` -> internal APK (`build/android/internal-debug.apk`).
3. `Android Release Candidate` -> release AAB (`build/android/release-candidate.aab`).

Export commands (from repo root):

1. `npm run android:export:singleplayer`
2. `npm run android:export:internal`
3. `npm run android:export:release`

If Godot is not in PATH, set `GODOT_BIN` to the executable path.
The exporter now falls back to the Android Gradle template automatically when Godot's direct Android export returns a generic configuration error.

## Runtime Config

Generated config source:

1. `godot/data/config.json` is generated by `npm run generate:godot-config`.
2. `godot/data/character_options.json` is generated by `npm run generate:godot-character-options`.
2. Long-term contract: endpoint paths in this file are relative to `apiBaseUrl` (for example `/sync/command`, not `/api/sync/command`).
3. Any `/api/*` paths are normalized by the runtime layer to remain backward compatible.
4. Production profile generation is available via `npm run generate:godot-config:prod` and forces a non-localhost API host unless explicitly overridden (`GODOT_API_BASE_URL`).
5. Local singleplayer profile generation is available via `npm run generate:godot-config:singleplayer` and sets `runtimeMode` to `singleplayer_local`.

Set these exports in the Godot editor on the `AuthClient` and `SyncClient` nodes when overriding defaults:

1. `AuthClient.api_key`: Firebase Web API key.
2. `SyncClient.api_base_url`: API host root, e.g. `https://<region>-<project>.cloudfunctions.net/api`.
3. `Main.run_id`: stable run ID for this save slot/session.

## Input

1. `WASD` / arrow keys: local movement (client-authoritative).
2. `E`: interact trigger precheck + immediate commit.
3. `F`: save local savepoint.
4. `L`: load the latest local save / reconcile from canonical state.

## Character Creation

1. Step order is `Name -> System -> Origin -> Race -> Class -> Multiclass -> Profession -> Attributes -> Skills -> Perks -> Starter Tree -> Alignment -> Review`.
2. The `System` step is the core identity pick and comes before race/class/profession so it can filter later options.
3. Skills are no longer loadout-only. The creator now shows:
   - system-granted skills
   - profession-granted skills
   - elective active skills
   - elective passive skills
   - filtered loadouts
4. Godot uses the same generated canonical system subset as the web creator instead of a handwritten placeholder archetype list.

## Trigger Model Notes

1. `ENTER_TILE` commits are batched (`<=100ms`, max 4).
2. `INTERACT`, `ZONE_EXIT`, `ENCOUNTER_GATE`, `SAVEPOINT` flush pending batch and send immediately.
3. Client prechecks are local (distance, LoS, cooldown).
4. In `online`, the backend remains authoritative for trigger validation and state transitions.
5. In `singleplayer_local`, the Godot local sync client mirrors the same canonical state shape in `user://`.

## Story Client Notes

1. `online` mode uses `/story/start` and `/story/poll` (relative to `apiBaseUrl`).
2. `singleplayer_local` mode never performs story HTTP calls and instead generates deterministic local prose from map, quest, and system context.
3. World state changes keep a local fallback prose payload active before remote story arrives.

## Pixel Map Foundation

1. `PixelMapRenderer` draws map tiles and trigger markers from `world_manifest.json`.
2. `WorldController` calls renderer updates on map changes (`_update_scene_for_map`).
3. Hub traversal now includes three maps (`map_village_square` -> `map_training_glade` -> `map_ruined_outlook`).
4. `SpriteHooks` (`PlayerSpriteAnchor`, `GuideSpriteAnchor`) are updated by the controller for future sprite replacement passes.
5. Placeholder runtime art pack currently lives under `godot/assets` and is generated with `npm run generate:godot-assets:placeholder`.

## Perf Baseline Probe

1. Run `npm run test:godot:perf` to execute headless map-traversal instrumentation.
2. The command writes a baseline report under `docs/reports/godot_map_traversal_perf_baseline_<date>.md`.
3. Metrics include traversal transitions plus average/p95 movement and render timings.
